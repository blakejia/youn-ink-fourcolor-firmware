## 阶段 0b：一次 USB 插回，只为刷入新的日志环（**已构建，等你**）

**发现（2026-10-09 凌晨）**：日志环装不下一个周期的尾部——设备在开机后
~5.5 s 上传，而画板决策行（`show page` / `skipping repaint`）在 10–15 s 才写，
于是它留在环里、被**下一轮**开机爆发挤掉。结果：**设备日志里永远看不到画板决策**，
而这正是判定那 25% 冗余下载所必需的证据。

修法：环 `kDataBytes` 2048 → **4096**（`.rtc_noinit` 实测 2068 → 4116 B，
RTC slow 段 8192 B，**余 5936 B**），上传上限同步 4096、服务端 ingest 4096 → 8192。
顺带修掉第二个耦合：`LOG_BODY_BUF`/`LOG_B64_BUF` 原本是字面量（注释承诺"跟随 cap"却没做到），
4096 B 载荷需 5464 B base64 塞进 3072 B 缓冲 ⇒ **每批静默截断**。已改为 `const fn` 派生。

**状态**：`cargo test 432` / `server pytest 338` / `idf.py build` 全绿，镜像 `0x2c9f50`
已构建。**刷入失败**（设备已按计划在 `00:35` 转电池，USB 端口消失）。提交 `5a6c342`。

**你需要做的**：下次插回 USB 时告诉我，我立刻刷入（约 30 s），然后你照常拔线继续跑。
**这一插拔不是新需求**——它就是你原本要做的"接触 2"开始的那一次插回。

**顺带纠正一个我算错的数字**：我在 `2026-10-09-paint-reduction-options.md` 里写"刷屏是
内容需要的 **6 倍**"是错的（分母用了 15 次唤醒，应该用 90 分钟轮换在 158 分钟里需要的
5.27 次换页）。严格复算是 **2.28 倍**；再按 MCP upsert 日志拆开：外部客户端**每 30 分钟

## 阶段 2：需要插线回 USB 的项（**你做，共 3 次短操作**）

这些必须在**插着 USB** 时做（屏幕/LED/按键才有效），且**不冲突**——可以一次做掉。

### 2.1 设置页/通知/按键观感（红线③④，肉眼）

**目的**：这是探针**无法**替代的部分——探针只验逻辑，不验**画面对不对**。

1. 插着 USB，等屏幕出画（对话页）
2. 长按 **BOOT 1 秒** → 进设置页；看**设置页是否正常显示**（左导航 + 右列表，文字清晰不糊）
3. 短按 **DOWN** 两次 → 到「网络」；短按 **BOOT** → 进选项；**BOOT 单击 3 次**让「日志上报」转一圈，看**对勾/状态是否跟着变**
4. **UP** 回导航，**UP** 回「系统」→ **BOOT** 进选项 → **DOWN DOWN** 到「重置设备」→ **BOOT 一次**（只 arm，会显示"5 秒内再按一次"，**不要按第二次**）→ 看提示文字是否正常
5. **UP** 退出设置页 → 看**是否回到对话页**
6. 我从服务端 push 一条通知 → 看**通知是否上屏**；点 **BOOT** 确认 → 看**是否回到画板页**且文字正常

**判据**：以上每一步屏幕都要有正确反应，文字**不糊、不缺笔画**（这是红线④画质，探针验不了）。

### 2.2 LED 五态（肉眼）

代码推导表已定（`led_policy.rs`，纯函数 + 单测），我只需要你**看灯**：

| 状态 | 期望（按代码） | 怎么造 |
|---|---|---|
| 充电中 | 亮 200 ms / 灭 2800 ms（慢闪） | 插着 USB 充电池 |
| 充满 | **常亮** | 充满后 |
| 放电空闲 | **常灭** | 拔线静置 |
| 有活动脉冲 | 亮 120 ms / 灭 180 ms（快闪一下） | 拔线后按任意键 |

**注意**：LED 是 GPIO3，在板子背面。充电中和空闲两个状态**不可能同时观察**——所以这轮要么插线看充电/充满，要么拔线看空闲/脉冲。**建议插线时看前两个，拔线后看后两个**（正好和阶段 1 同一轮）。

### 2.3 音频（用耳朵）

**已知缺陷预警**：运行期**音频轨无法恢复**——`rf_rails_audio(0)`（刷屏前关轨）在
全仓**只有一处调用**，`PowerAudioOn()` 只在开机 `InitializePower()` 里（一次性）。
`AudioService::CheckAndUpdateAudioPowerState` 只管 codec 的 input/output enable，
**不管 power/amp 轨**。所以 T2 把关轨提前到刷屏前之后，**在"继续活着的会话"里可能再也发不出声**。

**怎么验**：
1. 插着 USB（设备常亮不睡），在对话页
2. 我从服务端 push 一条通知 → 听**有没有提示音**
3. 若无声 → 这就是上面那个缺陷的**正向证据**（不是你的错觉，是真 bug）

**这一项我特别需要你的耳朵**——日志里看不到功放有没有出声。

## 最省事的执行顺序

1. **现在（插着 USB）**：做 2.1 的 6 步 + 2.2 的前两态 + 2.3 的耳朵测试
2. **然后**：拔掉 USB，放电池上，什么都不做，**2 小时**
3. **2 小时后**：告诉我一声，我拉对照报告（阶段 1 的 7 项全部有数据）
4. **可选**：阶段 1 结束后拔电池重插一次（验崩溃前日志存活）

这样**总共 3 次物理接触**（1 次长按操作 + 1 次拔线 + 1 次可选拔电池），
覆盖目前所有需要物理条件的项目。
